# 11 · 口述稿（Interview Script）

> 四套口述稿：30 秒 / 1 分钟 / 3 分钟 / 8~10 分钟。工程师口吻，避免背稿腔。可直接照着练，括号内是"停顿/切换"提示。

---

## 一、30 秒（自我介绍/电梯版）

> 我是尤译庆，2027 届嵌入式软件工程师校招候选人，目前在深圳维特智能实习。实习主要做两件事：一是杰理 AC632N 蓝牙模块的驱动和低功耗设计——在一个闭源的厂商 SDK 上完成了 SPP+BLE 固件的构建、烧录、蓝牙改名，还写了硬件自检和低功耗门控；二是把调试流程工具化——用 Python 写了一套 1 Mbps 串口日志接收工具，带 tkinter GUI 并打包成 Windows exe，外加 BLE 扫描脚本，最后还做了钉钉日报的 PPT 自动化。这个仓库就是我的开发工作区完整镜像。

---

## 二、1 分钟（项目概览版）

> 这个仓库叫 `ac632n-dev-tools`，是我在杰理 AC6321A 蓝牙开发工作区的完整备份，可以理解成"厂商 SDK + 我自研的一套工具链"。
>
> 先说固件侧：目标应用是 `apps/spp_and_le`（SPP 经典蓝牙 + BLE 双模透传），平台是 bd19。我在 SDK 上做的真实改动有 6 个文件——加了 `[WTYI]` 启动打印和 5 秒 UART 心跳、ADC/IIC/SPI 硬件自检、以及一个 BLE 动态改名 demo（每 10 秒在两个名字间切换并重建广播包）。还解决了"改了 `.edr_name` 却还被配置区旧名覆盖"的问题。
>
> 再说工具侧：写了三个 Python 工具——串口日志接收（默认 1000000 波特率）、tkinter GUI（多线程 + 队列，PyInstaller 打包成 exe）、BLE 扫描（bleak 按关键字匹配）；八个一键 bat 加一个带参数校验的 PowerShell 改名脚本。
>
> 最后是产品固件 `WT9011DCL-BT50`：我做了 SPI 六轴 IMU、IIC 磁力计、ADC 电池的驱动，和一层基于 SDK `REGISTER_LP_TARGET` 的低功耗门控，配套写了引脚映射和低功耗设计文档。

## 三、3 分钟（标准版，分三层）

**开场（10 秒）**
> 我挑这个仓库讲，是因为它能同时体现"嵌入式底层"和"工程自动化"两条线。

**第一层：工具链闭环（60 秒）**
> 杰理的工具链在 Windows 上，编译链装在 `<sdk_path>\pi32` 和 `<sdk_path>\mc`，构建命令是 `make ac632n_spp_and_le`。我把"打开工程、构建、烧录、列串口、收日志、改蓝牙名"全部封装成双击 bat，还写了一个 `env_check` 脚本一键自检环境。
> 其中最有意思的是蓝牙改名：`set_bt_name_and_build.ps1` 用正则改 `user_cfg.c` 里的 `.edr_name`，但改完我发现名字还是旧的——排查下来是配置区（flash 里的 syscfg）存了旧名，运行时会把代码默认值覆盖掉。所以我在 `cfg_file_parse()` 里又强制 `bt_set_local_name` 一次，产品固件里干脆 `syscfg_write` 把新名写回配置区持久化。这个"代码默认值 vs 配置区持久值"的坑，是这次实习印象最深的。

**第二层：串口日志工具（60 秒）**
> 板子 UART 日志走 PA00、波特率 1000000，但板子的 Type-C 不是串口口，得接 USB-TTL。我写了 `serial_log_receiver.py` 落盘，后来又做了 `uart_print_gui.py`——tkinter 多线程，读线程往 `queue.Queue` 塞字节，主线程每 100ms 消费渲染，因为 tkinter 不是线程安全的。打包成 `JieLi_UART_Print_Receiver.exe` 给没 Python 环境的同事用。日志里能看到真实数据，比如广播包 hex `02 01 06 03 03 30 AF ...`，我据此验证了改名真的刷新了广播。

**第三层：产品固件 + 低功耗（50 秒）**
> 产品板 WT9011DCL-BT50 用 AC6321A4，板载 QMI8685A 六轴、QMC5883P 磁力计、电池 ADC。我写了 `wtyi/` 驱动模块和硬件自检，低功耗上没直接 sleep，而是在 SDK 的 `REGISTER_LP_TARGET` 上加了 busy-flags 门控，任一外设忙就阻止休眠。文档里我诚实写了"没有实测电流"，只交付了可回退的框架。

**收尾（10 秒）**
> 这套东西的核心价值不是用了 SDK，而是在闭源工具链之上，把"构建-烧录-调试-改名-低功耗"做成了可复用、可复现、可自证的闭环。

## 四、8~10 分钟（深度版，可现场翻代码）

**0~2 分钟：定位 + 架构（配合 `02_SYSTEM_ARCHITECTURE.md` 的图讲）**
> （打开仓库）先一句话定位：这不是单一产品工程，是我在杰理 AC632N 蓝牙开发的工作区镜像，分三层——第三方 SDK（只读）、我改的固件（C）、自研工具集（Python/bat），外加一份产品固件。
> （画/指架构图）核心两条链路：构建→烧录→调试闭环，和 UART 日志链路。构建用 `make ac632n_spp_and_le`，产物 `update.ufw`/`jl_isd.fw`，`download.bat` 走 USB UBOOT 烧录；日志是固件 `printf` → PA00 @ 1 Mbps → USB-TTL → pyserial → 文件 + GUI。

**2~4 分钟：UART 日志工具（现场开 `uart_print_gui.py`）**
> 重点讲多线程 + 队列：读线程只 `rx_queue.put`，主线程 `after(100ms)` 消费，因为 tkinter 非线程安全。再讲 `timeout=0.2` 是读超时不是波特率，落盘用 `ab` 保真、显示才 `errors=replace` 容错。当场指出日志里的 `IPP` 碎片是高波特率伪影，体现"从日志反推问题"的能力。

**4~6 分钟：蓝牙改名 + 动态改名（开 `ble_trans.c` 搜 WTYI）**
> 讲三层：`.edr_name` 是经典名；配置区旧名覆盖的根因和"强制覆盖/写回"两种解法；`wtyi_dynamic_ble_name_switch()` 的"关广播→改名→重建包→开广播"时序。对照日志 `trans_adv_data(26)` vs `(28)` 证明广播包真的变了。

**6~8 分钟：低功耗门控 + 板级 bring-up（开 `low_power_design.md` + `hardware_map.md`）**
> 讲 `REGISTER_LP_TARGET` 机制 + busy flags 门控；讲从原理图/BOM/实物照片反推引脚映射，以及 CAD 库复用陷阱（BMI160 vs QMI8685A）。强调"诚实工程"：不声称实测电流。

**8~10 分钟：收尾 + 主动暴露可改进点**
> 主动说短板：硬编码 `<workspace>` 不可移植、串口无自动重连（需求里有但没实现）、GUI 高流量可能卡（没实测）。展示"我知道它不完美，而且知道怎么改"，比只报喜更可信。
